# Task 2 - Story Fidelity Validation & Retry (Validation Only)

## Objective

Implement deterministic validation and retry behaviour for the outputs
generated by Task 1.

Assume **Task 1 (Generation Pipeline Refactor)** has already been
completed.

This task is responsible ONLY for validating and enforcing generation
quality.

------------------------------------------------------------------------

# Scope

This task MUST NOT:

-   Redesign prompt templates
-   Modify Script Enhancement
-   Modify Scene Planning
-   Modify Scene Analysis
-   Modify Visual Prompt generation logic

Those belong exclusively to Task 1.

------------------------------------------------------------------------

# Phase 1 - Audit Existing Validation

Inspect the current implementation of:

-   Faithfulness validation
-   Prompt validation
-   Retry mechanism
-   Scene validation

Document:

-   Inputs
-   Outputs
-   Failure conditions
-   Retry flow
-   Weaknesses

Do not change behaviour during the audit.

------------------------------------------------------------------------

# Phase 2 - Human Classification

Replace the current boolean approach:

HAS_HUMAN

with the following classifications:

-   NO_HUMAN_ALLOWED
-   HUMAN_OPTIONAL
-   HUMAN_REQUIRED
-   NAMED_PERSON_REQUIRED

Apply this consistently across all validators.

------------------------------------------------------------------------

# Phase 3 - Story Fidelity Validator

Validate every generated prompt against the Scene Analysis produced by
Task 1.

Checks must include:

-   Characters match Scene Analysis.
-   No invented characters.
-   No invented events.
-   Primary subject is correct.
-   Primary action is present.
-   Narration is represented.
-   Emotional beat is preserved.
-   Environment matches.
-   Camera information exists.
-   Scene continuity is maintained.

Reject prompts that violate these rules.

------------------------------------------------------------------------

# Phase 4 - Symbolism Validator

Prevent symbolic replacement of the story.

Example:

Narration:

"The mother eagle encourages the chick."

Reject:

-   old man
-   weathered hand
-   candle
-   symbolic traveller

Accept:

-   mother eagle encouraging the chick

Symbolism may enhance a scene but must never replace the literal story.

------------------------------------------------------------------------

# Phase 5 - Realism Validator

Validate:

-   realistic scale
-   realistic proportions
-   realistic anatomy
-   realistic architecture
-   realistic object sizes
-   realistic bird sizes
-   realistic camera perspective
-   believable environmental scale

Reject prompts that violate real-world proportions.

------------------------------------------------------------------------

# Phase 6 - Retry Logic

When validation fails:

-   Do NOT regenerate successful scenes.
-   Do NOT regenerate the entire batch.
-   Regenerate only failed prompts.

Pass structured validator feedback back to the model.

Example:

FAILED

Reason: Unsupported character detected.

Allowed characters:

-   Mother Eagle
-   Eagle Chick

Please regenerate while preserving the original story, narration and
Scene Analysis.

------------------------------------------------------------------------

# Phase 7 - Validation Errors

Return specific errors instead of generic failures.

Examples:

-   Unsupported character detected.
-   Unsupported event detected.
-   Narration not represented.
-   Primary action missing.
-   Emotional beat missing.
-   Environment mismatch.
-   Human classification violated.
-   Unrealistic proportions.
-   Unrealistic perspective.
-   Story continuity broken.

------------------------------------------------------------------------

# Phase 8 - Regression Tests

Add tests covering:

-   Story fidelity
-   Character validation
-   Event validation
-   Human classification
-   Symbolism rejection
-   Narration fidelity
-   Continuity validation
-   Realistic proportions
-   Realistic perspective
-   Retry behaviour

------------------------------------------------------------------------

# Phase 9 - Backward Compatibility

Preserve existing JSON schemas wherever practical.

Minimise breaking changes.

Ensure existing projects continue to work.

------------------------------------------------------------------------
