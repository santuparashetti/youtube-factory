─────────────────────────────────────────
ANTI-JERK RULES — apply to every motion expression
─────────────────────────────────────────
These are non-negotiable constraints on every FFmpeg expression
generated by build_zoompan_filter(). Violating any one of these
produces visible camera shake or jerk in the output.

RULE 1 — Frame-count safety
  total_frames = max(1, round(duration * fps))
  Never divide by (total_frames - 1) directly in the expression.
  Use: inv_n = 1.0 / max(total_frames - 1, 1)
  This prevents division by zero on single-frame scenes.

RULE 2 — Expression boundary guarantee
  Every zoom expression must satisfy:
    at on=0:              z == start_scale   (exactly)
    at on=total_frames-1: z == end_scale     (exactly)
  Test this by evaluating the expression at both boundaries before
  returning it. If floating point drift exceeds 0.001, add a clamp:
    z = 'max(start, min(end, <expression>))'

RULE 3 — Easing curve starts and ends clean
  Every easing function t(on) must satisfy:
    t(0) = 0.0  exactly
    t(total_frames-1) = 1.0  exactly
  For sine: sin(PI/2 * 0) = 0 ✓, sin(PI/2 * 1) = 1 ✓
  For power curves: verify the exponent doesn't cause undershoot at t=1.
  Add explicit clamp on t: t = min(1.0, max(0.0, <curve>))

RULE 4 — Compound motion axis phasing
  When z, x, and y all move simultaneously, they must all use the
  SAME easing curve and the SAME t expression.
  Never mix easing curves across axes in the same motion type.
  Example of what NOT to do:
    z uses sine_power (slow start)
    x uses linear (immediate movement)
  This creates a lurch because x starts moving before z does.
  Correct: all three axes share one t, scaled by their own magnitude.

RULE 5 — Breathing phase continuity
  Breathing expressions use sin(2*PI*on/period).
  At on=0, sin(0) = 0, so every breathing scene starts at the
  baseline scale with zero velocity. This is correct — it means
  every scene starts from rest, which prevents cross-scene snaps.
  Do NOT add a phase offset to breathing expressions.
  The periods defined (z/2.1, x/1.7, y/3.3) are chosen so no
  period equals the scene duration, preventing a visible loop-snap
  at the end of the scene.

RULE 6 — Micro drift secondary axes
  Secondary axis drifts (the ±0.005 lateral, ±0.008 vertical added
  to zoom motions) must be small enough that they never approach
  the crop boundary at any frame.
  Maximum safe secondary drift magnitude: 0.012 (1.2% of frame width).
  Run _clamp_drift() on ALL drift values including secondary axes
  before inserting them into the expression string.

RULE 7 — Transition overlap protection
  The fade-in covers the first N frames and fade-out covers the
  last M frames. Motion during these frames is hidden.
  Do NOT start the primary motion move during the fade-in window.
  Implement a motion delay: the easing t should be computed from
  (on - fade_in_frames) rather than from on=0, clamped to [0,1].
  This means the camera is still during the fade-in, starts moving
  as the image becomes fully visible, and finishes before the
  fade-out begins.

  fade_in_frames  = transition_in.duration_frames   (from TransitionPlanner)
  fade_out_frames = transition_out.duration_frames
  active_frames   = total_frames - fade_in_frames - fade_out_frames
  t = max(0, min(1, (on - fade_in_frames) / max(active_frames - 1, 1)))

  Pass fade_in_frames and fade_out_frames into build_zoompan_filter()
  as optional parameters (default 0 for backward compatibility).

RULE 8 — No expression produces z < 1.0
  Any zoom value below 1.0 causes FFmpeg to zoom out beyond the
  image boundary, producing black bars or distortion.
  Wrap every z expression: z = 'max(1.001, <expression>)'
  The 1.001 minimum (not 1.0) gives a 0.1% safety margin for
  floating point evaluation at frame boundaries.

RULE 9 — Supersample consistency
  When supersample=2, all expressions use out_w=2560, out_h=1440.
  The clamping expressions iw*zoom-out_w and ih*zoom-out_h must
  use the supersampled dimensions, not the output dimensions.
  Verify this is consistent across ALL motion types including new ones.

RULE 10 — Test expression before returning
  After building the filter string, run a lightweight validation:
  evaluate the z expression at on=0, on=total_frames//2, on=total_frames-1
  using Python math (not FFmpeg). If any value is outside [1.0, 2.0]
  or the delta between consecutive sampled frames implies more than
  0.015 scale change per frame, log a warning and clamp.
  (0.015 per frame at 30fps = 0.45 per second maximum scale velocity —
  above this threshold motion becomes visibly jerky regardless of easing.)

These are the minimum values for motion to be perceptually visible

EASING — replace _t_factor() with this implementation:

  All curves operate on normalized t = on / (total_frames - 1)
  expressed as an FFmpeg arithmetic expression on the 'on' variable.

  linear:       t
  ease_in:      t*t
  ease_out:     1-(1-t)*(1-t)
  ease_in_out:  t*t*(3-2*t)                    ← smoothstep (keep existing)
  sine:         sin(PI/2*t)                    ← requires FFmpeg built with sin()
  sine_power:   sin(PI/2*t)^1.8               ← asymmetric, lingers at start
  cubic:        t*t*t
  quint:        t*t*t*t*t
  settle:       sin(PI/2*t)^0.7               ← fast start, long settle

  Verify FFmpeg supports sin() and PI in filter expressions before using.
  If not available, approximate sine with: 3*t*t - 2*t*t*t (smoothstep fallback).

COMPOUND MOTION — rebuild build_zoompan_filter() so every motion type
uses simultaneous z + x + y expressions. No motion type should move
only one axis. Minimum compound rules:

  Any zoom motion (push/pull/reveal):
    z expression   — primary movement
    y expression   — secondary drift ±0.008 * t (toward subject anchor)
    x expression   — micro lateral ±0.005 * t (alternating by scene_index parity)

  Any drift motion:
    z expression   — very slow scale 1.03 → 1.06 (barely visible, adds depth)
    primary axis   — main drift as specified
    secondary axis — 30% of primary value, perpendicular (makes it feel natural)

  Breathing / hold motions:
    z oscillation  — sin with period ≠ scene_duration (prevents loop feel)
    x oscillation  — sin with different period from z, amplitude 40% of z
    y oscillation  — sin with different period from x, amplitude 60% of z

  Breathing periods — use these exact values to prevent visible looping:
    z period: scene_duration / 2.1
    x period: scene_duration / 1.7
    y period: scene_duration / 3.3

SUPERSAMPLING — keep at 2x but feed it into the zoompan at the
upsampled resolution so the downscale provides natural antialiasing
on the motion path. This is already done but verify it applies to
all new motion types.

CROP SAFETY — the existing _clamp_drift() function must apply to all
new drift values including the secondary/micro drifts added above.
Never let any expression cause FFmpeg to crop outside the image bounds.
Wrap every x and y expression in max(0, min(..., iw*zoom - out_w))
exactly as the existing code does.
